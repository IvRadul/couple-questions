# Вопросы для пары

Веб-приложение для двоих: партнёры по очереди отвечают на вопросы об отношениях,
система сравнивает ответы, начисляет очки, виртуальную валюту и достижения.

## Версия 2 — что нового

- **Роли в раунде.** Каждый раунд один партнёр — `answerer` (отвечает на вопрос
  "про себя" первым), второй — `guesser` (пытается угадать ответ, не видя его).
  Роли назначаются случайно при старте раунда.
- **Два типа вопросов:**
  - **Тип 1 (`open`)** — свободный текстовый ответ. Совпадение больше не
    определяется автоматическим нечётким сравнением текста — после того как
    `guesser` отправит догадку, именно `answerer` вручную решает, засчитать
    совпадение или нет (кнопки «Совпало» / «Не совпало»).
  - **Тип 2 (`choice`)** — вопрос с заранее заданными вариантами ответа.
    Оба партнёра выбирают вариант из списка, совпадение считается автоматически.
- **Паки вопросов.** Вопросы сгруппированы в паки (`QuestionPack`). Стартовый
  пак бесплатный и открыт всем парам сразу, остальные открываются за монеты —
  экран `/packs`.
- **Смена пары с сохранением прогресса.** Кнопка «Расформировать пару и
  создать новую» на экране игры вызывает `POST /couples/leave`. Монеты,
  достижения и статистика хранятся на пользователе, а не на паре, поэтому
  прогресс никуда не пропадает — можно тут же создать новую пару или
  присоединиться к другому коду.

⚠️ **Схема базы данных изменилась** (новые таблицы `question_packs`,
`question_options`, `couple_pack_unlocks`, переименованные поля
`GameRound.answerer_id`/`guesser_id` и т.д.). Если вы уже запускали версию 1,
удалите старый файл `backend/couple_questions.db` перед первым запуском —
иначе приложение будет падать из-за несовпадения схемы.

## Стек

- **Backend:** FastAPI (Python 3.11), SQLAlchemy, SQLite, WebSocket, JWT
- **Frontend:** Next.js 14 (App Router), TypeScript, Tailwind CSS

## Запуск backend

```bash
cd backend
python3.14 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env               # при необходимости отредактируйте JWT_SECRET_KEY
rm -f couple_questions.db          # если апгрейдитесь с версии 1 — см. предупреждение выше

uvicorn app.main:app --reload --port 8000
```

При старте приложение само создаёт таблицы SQLite (`couple_questions.db`) и
засеивает базу двумя паками вопросов (стартовый бесплатный + платный
«Воспоминания и мечты», оба типа вопросов) и 4 достижениями (`seed_data.py`).

API будет доступно на `http://localhost:8000`, документация Swagger — на
`http://localhost:8000/docs`.

## Запуск frontend

```bash
cd frontend
npm install

cp .env.local.example .env.local   # NEXT_PUBLIC_API_URL=http://localhost:8000

npm run dev
```

Приложение будет доступно на `http://localhost:3000`.

## Как проверить сценарий на два устройства

1. Откройте `http://localhost:3000` в одном браузере (или вкладке инкогнито) — это
   первый партнёр. Приложение автоматически зарегистрирует анонимного
   пользователя и предложит создать пару — нажмите «Создать код приглашения».
2. Откройте `http://localhost:3000` в другом браузере/вкладке инкогнито — второй
   партнёр. Введите полученный 6-значный код в форму «Присоединиться».
3. Оба клиента автоматически попадут на экран игры и подключатся к
   `/ws/{couple_id}` через WebSocket.
4. Любой из партнёров нажимает «Начать раунд» — сервер случайно выбирает
   вопрос (из открытых паков) и роли: `answerer` и `guesser`.
5. `answerer` отвечает на вопрос "про себя" (текстом или выбором варианта —
   зависит от типа вопроса).
6. Как только он отправлен, `guesser` получает уведомление `your_turn` и
   пытается угадать ответ.
7. Дальше в зависимости от типа вопроса:
   - **Тип `choice`** — совпадение определяется автоматически, оба сразу видят
     результат (`round_result`).
   - **Тип `open`** — `answerer` получает экран ручной проверки
     (`validate_request`) с обоими ответами и нажимает «Совпало» / «Не
     совпало»; после этого результат уходит обоим (`round_result`).
8. Каждый может оценить вопрос от 1 до 5 звёзд или пожаловаться на него.
9. На экране «Паки» (`/packs`) можно открыть дополнительный пак вопросов за
   монеты — доступен обеим сторонам пары сразу после разблокировки.
10. Кнопка «Расформировать пару и создать новую» внизу экрана игры вызывает
    `POST /couples/leave` — прогресс пользователя (монеты, достижения)
    сохраняется, можно тут же создать новую пару.

## Аутентификация

В приложении нет логина и пароля. При первом обращении фронтенд вызывает
`POST /auth/register`, backend создаёт анонимного пользователя и выдаёт JWT
(поля `user_id`, `couple_id`, `exp`). Токен сохраняется в `localStorage` и
подставляется в заголовок `Authorization: Bearer <token>` для всех
REST-запросов и как query-параметр `token` при подключении к WebSocket.
После создания/присоединения/выхода из пары токен перевыпускается, чтобы в
нём был актуальный `couple_id`.

## Дальнейшие шаги (не входит в каркас)

- Переход с SQLite на PostgreSQL: замените `DATABASE_URL` в `.env` на
  `postgresql+psycopg2://...` и добавьте `psycopg2-binary` в
  `requirements.txt` — благодаря SQLAlchemy код моделей менять не придётся.
  Для контроля миграций стоит добавить Alembic.
- Полноценная админ-панель поверх уже готовых `/questions/admin/*` и
  `/packs` эндпоинтов (сейчас это просто защищённые `is_admin` роуты).
- Push-уведомления, если партнёр офлайн (сейчас уведомление о ходе приходит
  только если оба клиента подключены к WebSocket — правда, при
  переподключении клиент теперь автоматически подтягивает состояние текущего
  раунда).
- История пар: сейчас старая (расформированная) пара просто перестаёт быть
  активной для обоих пользователей, но остаётся в БД со всей своей историей
  раундов. Экрана "мои прошлые пары" пока нет.
